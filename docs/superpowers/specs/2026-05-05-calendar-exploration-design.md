# 달력 탐색 경험 재설계

작성일: 2026-05-05
상태: 설계 승인 완료, 구현 전
범위: 달력 화면과 홈의 달력 진입 요약

## 1. 배경

현재 앱의 달력 화면은 날짜별 거래를 확인하는 기본 구조는 갖추고 있지만, 사용자가 특정 거래를 찾거나 수입과 지출 흐름을 나눠서 읽는 경험은 약하다.  
또한 홈에서는 달력으로 진입하는 흐름이 약하고, 달력의 핵심 정보를 간략히 읽을 수 있는 요약도 부족하다.

이번 재설계의 목표는 달력을 단순 날짜 뷰가 아니라 `돈의 흐름을 날짜 중심으로 탐색하는 화면`으로 바꾸는 것이다.

## 2. 목표

- 홈에서 달력으로 자연스럽게 진입할 수 있게 만든다.
- 달력 안에서 `전체 / 수입 / 지출` 흐름을 빠르게 전환할 수 있게 한다.
- 검색어를 걸어도 달력이라는 구조를 유지한 채 관련 날짜를 찾을 수 있게 한다.
- 날짜를 누르면 같은 화면 아래에서 그날의 거래를 시간순으로 읽을 수 있게 한다.
- 홈에서는 달력 관련 정보를 `건수 + 금액` 중심으로 간단히 보여준다.

## 3. 비목표

- 통계 화면 전체 재설계
- 하루 상세 전용 별도 화면 추가
- 태그, 다중 필터, 고급 검색 문법
- 캘린더 기반 편집 기능 확장

통계는 이번 구현 대상에서 제외한다. 다만 이후 통계도 같은 철학으로 확장할 수 있게 설계 원칙만 맞춘다.

## 4. 최종 구조

### 4.1 홈

홈에는 `달력 요약 카드`를 둔다.

이 카드는 다음 역할을 동시에 가진다.

- 오늘 기준 거래 건수 요약
- 오늘 기준 수입/지출 금액 요약
- 달력 화면으로 이동하는 진입 버튼

표현 원칙:

- 정보는 작고 간결하게 보여준다.
- `건수 + 금액`을 모두 보여주되, 홈의 요약 성격을 해치지 않게 압축한다.
- 달력 전체를 축소해서 보여주기보다, 오늘 기준 흐름을 읽게 하는 방식으로 유지한다.

### 4.2 달력 화면

달력 화면은 기존처럼 `달력 + 선택한 날짜의 거래 목록` 구조를 유지한다.  
단, 상단 탐색 기능을 강화해서 같은 화면 안에서 검색과 타입 필터가 함께 동작하게 만든다.

핵심 구조:

- 상단 달력 헤더
- 펼칠 수 있는 검색/필터 영역
- 날짜 셀 집계가 보이는 달력 본문
- 선택한 날짜의 거래 목록

## 5. 상호작용 설계

### 5.1 날짜 선택

- 사용자가 날짜를 누르면 별도 화면으로 이동하지 않는다.
- 같은 달력 화면 아래의 `선택한 날짜 거래 목록`만 갱신한다.
- 목록은 시간순으로 정렬한다.
- 수입과 지출이 섞여 있어도 시간순은 유지하고, 행 내부에서 타입을 구분한다.

이 선택은 달력의 탐색 흐름을 끊지 않기 위한 것이다.  
사용자는 월 전체 흐름을 보다가 특정 날짜의 상세를 바로 읽을 수 있어야 한다.

### 5.2 검색

- 달력 상단은 기본 상태에서 간결하게 유지한다.
- 사용자가 상단 영역을 끌어내리거나 펼치면 검색과 필터가 나타난다.
- 검색 대상은 거래 메모, 거래처명, 카테고리명이다.
- 검색 중에도 달력 형태는 유지한다.
- 검색 결과가 있는 날짜만 강조해서 보여준다.

중요 원칙:

- 검색 결과를 리스트 전용 화면으로 바꾸지 않는다.
- 달력은 항상 날짜 기반 탐색 구조로 남는다.

### 5.3 수입/지출 전환

- 타입 필터는 `전체 / 수입 / 지출` 3분할 토글로 구성한다.
- 체크박스 형태나 다중 선택 필터는 쓰지 않는다.
- 필터는 달력 집계, 날짜 강조, 선택 날짜의 거래 목록에 모두 일관되게 반영된다.

이 선택은 빠른 전환과 낮은 학습 비용을 우선하기 위한 것이다.

## 6. 데이터 설계

현재 달력 기능은 `CalendarSnapshot`과 `selectedCalendarTransactionsProvider` 중심으로 동작한다.  
이번 설계는 기존 구조를 유지하되, 탐색 상태를 추가하는 방식으로 확장한다.

새 상태:

- `calendarTypeFilter`
  - 값: `all`, `income`, `expense`
- `calendarSearchQuery`
  - 값: 검색 문자열

적용 범위:

- 주/월/년 달력 집계 계산
- 날짜 셀 강조 상태
- 선택한 날짜 거래 목록
- 홈의 달력 요약용 경량 집계

날짜 셀에 필요한 정보:

- 현재 필터와 검색 조건을 만족하는 거래 건수
- 그 날짜의 수입 합계
- 그 날짜의 지출 합계

홈 요약 카드용 정보:

- 오늘 거래 건수
- 오늘 수입 합계
- 오늘 지출 합계

## 7. UI 원칙

### 7.1 달력 셀

- 각 날짜는 해당 날짜의 거래 존재 여부를 빠르게 읽을 수 있어야 한다.
- 필터가 `전체`일 때는 수입/지출이 모두 반영된 숫자를 보여준다.
- 필터가 `수입` 또는 `지출`일 때는 해당 타입 기준 정보만 보여준다.
- 검색 중에는 결과가 있는 날짜를 시각적으로 더 강하게 보여준다.

### 7.2 선택 날짜 목록

- 화면 아래 목록은 `그날 어떤 흐름이 있었는지`를 읽는 영역이다.
- 시간순 정렬을 유지한다.
- 각 행은 타입, 금액, 시각, 핵심 메타데이터를 빠르게 읽을 수 있게 한다.
- 날짜를 바꿨을 때 이 영역만 자연스럽게 갱신된다.

### 7.3 홈 요약 카드

- 홈은 달력 전체 화면의 축약판이 아니라 진입 요약 역할만 한다.
- 정보량은 작게 유지한다.
- `오늘 몇 건`, `수입`, `지출` 정도만 보여주고, 탭으로서의 홈 정체성을 해치지 않는다.

## 8. 접근안 비교

### 접근안 A. 달력 중심 확장형

기존 달력 화면을 유지하면서 검색, 3분할 타입 필터, 날짜별 목록을 확장한다.

장점:

- 현재 구조를 가장 덜 깨뜨린다.
- 사용 흐름이 자연스럽다.
- 구현 범위가 집중되어 있다.

단점:

- 상단 확장 영역의 인터랙션이 어설프면 복잡해 보일 수 있다.

### 접근안 B. 검색 우선형

달력 상단에 검색창과 필터를 항상 노출한다.

장점:

- 검색 기능을 바로 발견하기 쉽다.

단점:

- 달력보다 컨트롤이 먼저 보이면서 화면이 무거워진다.
- 탐색보다 도구 느낌이 강해진다.

### 접근안 C. 하이브리드 상세형

달력을 유지하되, 날짜를 누르면 아래 목록이 크게 확장되어 반쪽 상세 화면처럼 동작한다.

장점:

- 하루 단위 탐색에는 강하다.

단점:

- 상태와 UI 복잡도가 커진다.
- 이번 범위에서는 과하다.

### 선택

이번 구현은 `접근안 A. 달력 중심 확장형`을 채택한다.

이유:

- 현재 앱 구조와 가장 자연스럽게 연결된다.
- 홈에서 달력으로 들어가고, 달력 안에서 바로 찾고, 같은 화면에서 읽는 흐름이 명확하다.
- 기능을 늘리되 화면의 본질을 바꾸지 않는다.

## 9. 테스트 방향

### 단위/상태 테스트

- 타입 필터가 `전체 / 수입 / 지출`에 따라 집계를 바꾸는지 확인
- 검색어가 메모, 거래처명, 카테고리명에 적용되는지 확인
- 검색 중에도 달력용 날짜 집계가 유지되는지 확인
- 선택 날짜 목록이 같은 필터/검색 상태를 공유하는지 확인

### 위젯 테스트

- 홈의 달력 요약 카드가 `건수 + 금액`을 모두 보여주는지 확인
- 달력 화면에서 검색/토글이 열리고 닫히는지 확인
- 날짜 탭 시 아래 목록만 갱신되는지 확인
- `수입`, `지출` 필터에 따라 목록과 달력 강조가 일관되게 바뀌는지 확인

### 수동 확인

- 홈에서 달력 진입이 자연스러운지
- 검색어를 걸어도 달력이 깨지지 않는지
- 특정 날짜의 거래를 시간순으로 읽기 쉬운지
- `전체 / 수입 / 지출` 전환이 빠르고 혼란이 없는지

## 10. 후속 원칙

- 통계 화면은 이번 작업에서 직접 구현하지 않는다.
- 다만 이후 통계도 `필터 가능한 탐색형 화면`으로 확장한다.
- 검색과 타입 전환의 철학은 달력과 통계가 최대한 일관되게 가져간다.

## 11. 구현 경계 요약

이번 구현에 포함:

- 홈의 달력 요약 카드 보강
- 홈에서 달력 화면 진입 강화
- 달력 화면의 검색 확장 영역
- `전체 / 수입 / 지출` 3분할 타입 필터
- 날짜 선택 시 같은 화면 아래 목록 갱신
- 검색 상태와 타입 필터를 반영한 날짜 셀 집계

이번 구현에서 제외:

- 통계 전체 재설계
- 하루 상세 별도 화면
- 복합 조건 필터
- 검색 결과 전용 화면
