# Recurring Spend Detection Spec

작성일: 2026-05-22  
기능 slug: `recurring-spend-detection`  
기능 크기: `medium`  
상태: draft

## 목적

이 문서는 다정가계부가 거래 내역으로부터 `반복적으로 나가는 돈`을 어떤 기준으로 판정할지 정의한다.

핵심 목표는 두 가지다.

1. 홈 첫 화면의 반복지출 카드가 신뢰를 잃지 않게 한다
2. 고정비, 구독, 반고정 생활비를 한 구조 안에서 다루되 초기 오탐을 최소화한다

## 전제

현재 데이터 모델에서 사용할 수 있는 핵심 필드는 아래와 같다.

- `type`
- `amount`
- `occurredAt`
- `accountId`
- `categoryId`
- `merchantName`
- `paymentMethod`
- `memo`

현재 없는 것:

- 위치 힌트
- 원문 출처
- 외부 금융사 원문 신뢰도
- 사용자 교정 이력

따라서 MVP 판정 로직은 `복잡한 AI 추론`이 아니라 `설명 가능한 규칙 기반`이어야 한다.

## 판정 목표

반복지출 판정 로직은 아래 질문에 답할 수 있어야 한다.

- 이 거래 묶음은 반복적으로 나가는 돈인가
- 그렇다면 어떤 종류의 반복지출인가
- 얼마나 확실한가
- 홈 카드에 바로 보여줘도 되는가

즉 출력은 단순 boolean이 아니라 아래 네 값을 가져야 한다.

- 반복지출 여부
- 반복 유형
- 신뢰 점수
- 노출 가능 여부

## 반복지출 유형

반복지출은 세 가지로 나눈다.

### 1. 고정비

예:

- 통신비
- 보험
- 월세
- 대출 상환
- 공과금

특징:

- 주기가 비교적 일정하다
- 금액이 일정하거나 변동폭이 작다
- 상호나 메모가 비교적 안정적이다

### 2. 구독

예:

- OTT
- 음악
- 앱 구독
- 멤버십

특징:

- 반복성 텍스트 단서가 비교적 강하다
- 금액이 작아도 정기성 의미가 크다
- 사용자가 줄일 후보로 인식하기 쉽다

### 3. 반고정 생활비

예:

- 비슷한 카페 소비
- 반복 배달
- 자주 반복되는 택시
- 특정 쇼핑 루프

특징:

- 완전히 고정된 지출은 아니지만 생활 습관처럼 반복된다
- 금액과 주기가 조금 더 유연하다
- 잘못 잡으면 오탐이 늘어나는 영역이다

## 전체 판정 구조

초기 버전은 `2단계 하이브리드형`으로 간다.

### 단계 1. 엄격 판정

고정비와 구독은 엄격한 규칙으로 먼저 판정한다.

목표:

- 확실한 반복만 빠르게 잡기
- 홈 첫 카드의 신뢰 확보

### 단계 2. 보수적 점수 판정

반고정 생활비는 점수 기반으로 후보를 계산하되, 점수가 충분히 높은 경우만 노출한다.

목표:

- 자동 해석의 범위를 넓히되
- 카드에 섣불리 올리지 않기

## 입력 단위와 비교 단위

판정은 개별 거래 하나가 아니라 `유사 거래 묶음(cluster)` 단위로 한다.

유사 거래 묶음의 기본 키 후보:

- `type`
- `accountId`
- 정규화된 `merchantName` 또는 `memo`
- 보조적으로 `categoryId`

우선순위는 아래와 같다.

1. `merchantName`이 있으면 merchant 중심
2. merchant가 없고 memo가 있으면 memo 중심
3. 둘 다 비어 있으면 반복 판정 대상에서 제외

## 정규화 규칙

거래명을 비교하기 전에 문자열을 정규화한다.

최소 정규화:

- trim
- 대소문자 무시
- 연속 공백 축약
- 특수문자 일부 제거

추후 확장 가능:

- 카드 승인 텍스트 접미어 제거
- 지점명/브랜치명 단순화
- 숫자 토큰 일부 제거

MVP에서는 과도한 정규화보다 안전한 수준만 적용한다.

## 단계 1: 고정비/구독 엄격 판정 규칙

아래 조건을 모두 만족하면 `확실한 반복`으로 본다.

### 공통 조건

- `type == expense`
- 최근 90일 안에 같은 묶음이 2회 이상 존재
- 거래명 키가 비어 있지 않음
- `transfer`는 제외

### 고정비 조건

- 같은 `accountId` 또는 동일 결제수단 힌트
- 금액 차이가 5% 이내 또는 절대 오차 허용 범위 이내
- 거래 간 간격이 20~40일 사이인 쌍이 1회 이상 존재

### 구독 조건

아래 중 하나를 만족:

- 텍스트에 구독성 단서가 있음
- 같은 상호/메모로 최근 90일 안에 2회 이상 반복
- 금액 차이 5% 이내

구독성 단서 예시:

- `subscription`
- `premium`
- `membership`
- `넷플릭스`, `유튜브`, `apple`, `google`, `spotify` 등 사전 등록 키워드

초기 사전은 작게 시작한다.

## 단계 2: 반고정 생활비 점수 판정

반고정 생활비는 boolean 규칙이 아니라 점수 합산 방식으로 계산한다.

점수 요소 예시:

- 거래명 유사도 높음: `+40`
- 같은 카테고리: `+15`
- 같은 계정 또는 결제수단: `+10`
- 최근 45일 내 3회 이상 등장: `+20`
- 금액 오차 15% 이내: `+10`
- 간격이 3~14일 패턴으로 반복: `+5`

감점 요소 예시:

- 금액 편차 과도: `-20`
- 거래명 공백 또는 정보 부족: `-30`
- 카테고리/상호가 자주 흔들림: `-15`

## 노출 기준

점수 계산 후 아래와 같이 분류한다.

- `80점 이상`: 높은 신뢰, 홈 카드 노출 가능
- `60~79점`: 후보 유지, 상세나 내부 목록에는 가능하나 홈 카드 기본 노출은 보수적
- `59점 이하`: 반복 후보로만 남기고 홈 카드에는 노출하지 않음

초기 버전에서는 홈 카드에 `80점 이상`만 올린다.

## 제외 규칙

아래 거래는 반복지출 판정에서 제외하거나 매우 보수적으로 본다.

- `type == transfer`
- 거래명과 메모가 모두 비어 있음
- 최근 1회만 나타난 거래
- 금액 편차가 지나치게 큼
- 명절/이벤트성 소비로 보이는 비정기 대형 지출

또한 아래는 초기엔 과감히 제외해도 된다.

- 현금성 메모만 있는 잡거래
- 상호 식별이 어려운 카드 승인 문자 수기 입력
- 동일 브랜드지만 목적이 자주 바뀌는 범용 마켓

## 홈 카드 노출 원칙

반복 판정이 된다고 모두 홈 카드에 올리지 않는다.

홈 카드 노출 조건:

- 반복 여부가 true
- 반복 유형이 분류됨
- 신뢰 점수가 기준 이상
- 사용자에게 설명 가능한 거래 묶음 이름이 있음

즉 카드에 올라가는 항목은 `확실하고 설명 가능한 반복지출`이어야 한다.

## 묶음 이름 결정 규칙

카드에 보여줄 이름은 아래 우선순위를 따른다.

1. 정규화 전 `merchantName`
2. merchant가 없으면 `memo`
3. 둘 다 부적절하면 카드 노출 제외

브랜드명과 메모가 함께 있을 때는:

- 카드 제목은 브랜드명
- 상세 보조문구에 메모를 사용

## 반복 유형 라벨링

카드와 상세에서 사용할 라벨:

- `고정비`
- `구독`
- `생활 반복`

초기에는 이 세 개만 쓴다.  
세부 라벨 분해는 후속 기능으로 미룬다.

## 데이터 기간 기준

초기 계산 기간 추천:

- 고정비/구독: 최근 90일
- 반고정 생활비: 최근 45일
- 홈 카드 집계: 이번 달 기준 합산

이유:

- 고정비와 구독은 월간 주기를 보기 위해 최소 2~3개월이 유리함
- 반고정 생활비는 너무 길게 보면 노이즈가 많아짐

## 신뢰 우선 원칙

이 로직의 최우선 원칙은 `더 많이 잡는 것`이 아니라 `틀리지 않는 것`이다.

왜냐하면:

- 반복지출 카드는 홈 첫 보상이다
- 첫 보상이 틀리면 앱 전체 신뢰가 깨진다
- 자동기입형 앱에서 신뢰 손실은 회복 비용이 크다

따라서 초기엔 누락이 있더라도 오탐을 줄이는 쪽을 택한다.

## 성공 기준

이 로직이 잘 설계됐다고 볼 기준:

- 고정비/구독은 사람이 봐도 납득되는 수준으로 잡힌다
- 반고정 생활비는 과하게 잡히지 않는다
- 카드에 노출된 항목을 사용자가 설명 가능하다고 느낀다
- 같은 데이터로 다시 계산해도 결과가 크게 흔들리지 않는다

## 실패 신호

- 우연한 두 번 결제가 반복지출로 뜬다
- 카페/편의점 같은 일상 소비가 과도하게 반복으로 묶인다
- 카드에 올라온 이름이 모호해서 사용자가 무엇인지 모른다
- 반복지출 총액이 실제 체감보다 부풀려진다

## 후속 확장

후속 버전에서 확장할 수 있는 것:

- 위치 힌트 포함
- 알림 원문/출처 신뢰도 포함
- 사용자 교정 피드백 반영
- 브랜드 사전 강화
- 구독/고정비/생활 반복 하위 타입 세분화
