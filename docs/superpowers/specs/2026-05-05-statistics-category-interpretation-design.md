# 통계 화면 `지출 카테고리 해석 우선형` 설계

## 요약

현재 통계 화면은 `기간 선택 + 숫자 요약 + 차트` 구조에 가깝다.  
이번 작업에서는 통계의 1차 역할을 `숫자를 나열하는 화면`이 아니라 `이번 기간에 돈이 어디로 가장 많이 갔는지 읽어주는 화면`으로 재정의한다.

첫 버전은 `지출만` 다룬다.  
핵심 구조는 다음과 같다.

- 상단: `이번 기간 소비 해석` 카드
- 본문: `상위 지출 카테고리 목록`
- 하단: 기존 차트는 보조 참고 영역으로 낮춘다

이 방향은 홈의 소비 해석 카드, 달력의 탐색형 구조와 같은 철학을 공유한다.

## 문제 정의

현재 통계 화면은 다음 한계가 있다.

- 사용자가 `숫자는 보이는데 의미는 바로 안 읽힌다`
- 차트가 먼저 보이지만, 무엇을 해석해야 하는지 안내가 약하다
- 카테고리 영역이 있어도 `이번 기간의 소비 중심`이 명확하게 전달되지 않는다
- 달력 화면에서 만든 `탐색하면서 읽는 흐름`이 통계에는 아직 이어지지 않는다

즉, 통계 화면은 존재하지만 `내 소비를 이해시켜 주는 화면`으로는 아직 부족하다.

## 목표

- 이번 기간의 소비 중심 카테고리를 상단에서 바로 읽어준다
- 사용자가 `내 돈이 어디에 가장 많이 갔는지` 한 번에 이해할 수 있게 한다
- 숫자와 차트보다 `해석`을 먼저 배치한다
- 과장하거나 훈계하지 않고, 자연스러운 한국어 앱 문체를 유지한다

## 비목표

- 수입 카테고리 해석
- 예측형 통계
- 기간 대비 증감 분석
- 건수 기반 패턴 분석
- 통계 화면의 전체 IA 재설계
- 차트 시스템 제거

이번 범위는 `지출 카테고리 해석을 상단 핵심 역할로 승격`하는 것에 한정한다.

## 접근안 비교

### 1. 해석 우선형

- 상단 해석 문구
- 상위 지출 카테고리 목록
- 차트는 하단 참고

장점:
- 지금 앱의 톤과 가장 잘 맞는다
- 사용자가 의미를 먼저 읽고, 숫자는 나중에 확인하게 된다
- 홈의 소비 해석 카드와 연결감이 생긴다

단점:
- 전형적인 통계 앱을 기대한 사용자에게는 덜 익숙할 수 있다

### 2. 차트 우선형

- 차트를 먼저 보여주고
- 해석 문구는 보조로 둔다

장점:
- 익숙한 통계 화면 구조다

단점:
- 지금 앱이 지향하는 `읽어주는 화면`의 결이 약해진다

## 결정

이번 구현은 `해석 우선형`으로 간다.

## 화면 구조

### 1. 기간 선택 패널

기존 구조를 유지한다.

- `이번 달 / 최근 3개월 / 전체`
- 월 이동 버튼

이 영역은 탐색 시작점 역할을 유지한다.

### 2. 상단 소비 해석 카드

새 핵심 영역이다.

구조:

- 제목: `이번 기간 소비 해석`
- 메인 1줄: 이번 기간에 가장 크게 보이는 지출 카테고리 해석
- 근거 1줄: 왜 그렇게 읽었는지 짧은 사실 제시
- 보조 칩: 순위 카테고리, 비중, 총 지출 건수 정도만 제한적으로 노출 가능

예시:

- 메인: `이번 기간엔 식비 쪽 지출이 가장 크게 모였어요.`
- 근거: `지출의 38%가 식비에 모였고, 총 12건이 기록됐어요.`

문장 원칙:

- 짧고 담백할 것
- 지출을 읽되 평가하지 않을 것
- 상단 메인은 한 문장만 둘 것
- 근거는 최대 두 사실까지만 연결할 것

금지 톤:

- `지출 관리가 잘 되고 있어요`
- `조심해야 할 소비예요`
- `지금 바로 줄이세요`

### 3. 상위 지출 카테고리 목록

해석 카드 아래에 배치한다.

노출 규칙:

- 최대 4개 카테고리까지 우선 노출
- 각 행은 `카테고리명 / 금액 / 비중`
- 순위를 1위부터 명확하게 보이게 한다

첫 버전에서는 `건수`는 제외한다.  
이유는 정보량이 늘어날수록 읽는 속도가 떨어지기 때문이다.

### 4. 숫자 요약 패널

기존의 수입/지출/잔액/건수 요약은 유지할 수 있다.  
다만 상단 소비 해석 카드보다 아래에 위치해야 한다.

즉, 우선순위는:

1. 해석
2. 카테고리 읽기
3. 숫자 요약
4. 차트

### 5. 차트 영역

차트는 제거하지 않는다.  
하지만 상단 핵심 영역이 아니라 `참고 영역`으로 내린다.

역할:

- 이미 상단에서 읽은 내용을 시각적으로 다시 확인하는 용도

즉, 차트가 화면을 설명하는 것이 아니라, 해석을 보조하는 구조로 바꾼다.

## 데이터 설계

기존 `StatisticsSnapshot`는 기본 합계와 카테고리 목록만 제공한다.  
이번 작업에서는 상단 해석 카드가 별도 로직으로 동작할 수 있도록 `지출 카테고리 해석용 파생 데이터`를 추가한다.

### 추가 구조

- `StatisticsCategoryInterpretation`
  - `headline`
  - `evidence`
  - `topCategoryLabel`
  - `topCategoryShare`
  - `expenseTransactionCount`

또는

- `StatisticsSnapshot` 안에서 계산 가능한 최소 데이터만 추가

권장 방향:

- 해석 결과를 만드는 함수를 presentation 밖으로 분리한다
- UI 위젯 안에서 직접 문구 분기하지 않는다

예시 인터페이스:

`buildStatisticsCategoryInterpretation(StatisticsSnapshot snapshot) -> StatisticsCategoryInterpretation`

## 해석 규칙

우선순위는 단순하게 간다.

1. 지출 데이터 없음
2. 상위 카테고리 집중형
3. 일반 상위 카테고리 안내

### 데이터 없음

- 메인: `아직 이 기간의 지출 흐름은 조금 더 쌓여야 보여요.`
- 근거: `지금은 카테고리별로 읽을 만큼 지출 기록이 많지 않아요.`

### 상위 카테고리 집중형

조건 예시:

- 1위 카테고리 비중이 35% 이상

표현 예시:

- 메인: `이번 기간엔 식비 쪽 지출이 가장 크게 모였어요.`
- 근거: `지출의 38%가 식비에 모였고, 총 12건이 기록됐어요.`

### 일반 상위 카테고리 안내

표현 예시:

- 메인: `이번 기간엔 생활비 성격의 지출이 먼저 보이고 있어요.`
- 근거: `식비와 장보기 비중이 가장 크고, 그다음은 교통이에요.`

첫 버전은 지나치게 많은 패턴을 읽지 않는다.  
핵심은 `가장 크게 보이는 지출 카테고리`를 공감 가능하게 읽어주는 것이다.

## 테스트 계획

### 단위 테스트

- 지출이 없을 때 데이터 없음 해석 반환
- 상위 카테고리 비중이 높을 때 집중형 해석 반환
- 상위 카테고리가 있어도 비중이 낮으면 일반 해석 반환
- `미분류` 카테고리도 문구가 깨지지 않는지 확인

### 위젯 테스트

- 통계 화면에서 상단 소비 해석 카드가 렌더링되는지
- 상위 카테고리 목록이 최대 4개까지 노출되는지
- 달력/내역 바로가기 버튼이 계속 보이는지

### 회귀 확인

- 기존 기간 변경 동작 유지
- 기존 차트 렌더링 유지
- 기존 숫자 요약 패널 유지

## 구현 범위

이번 구현에 포함:

- 상단 소비 해석 카드 추가 또는 기존 인사이트 패널 대체
- 해석 빌더 로직 분리
- 상위 지출 카테고리 목록 정리
- 테스트 추가

이번 구현에 제외:

- 수입 해석
- 기간 비교형 문구
- 건수 기반 소비 패턴 해석
- 필터형 통계 탐색
- 통계 화면 전체 라우팅 재설계

## 결정 요약

- 통계의 첫 개선 축은 `지출 카테고리 해석`
- 상단 핵심 메시지는 `이번 기간에 어디에 돈이 가장 많이 갔는지`
- 화면 구조는 `상단 해석 문구 + 아래 상위 카테고리 목록`
- 차트는 유지하되 보조 역할로 낮춘다
