# 통계 화면 `전체 / 수입 / 지출` 탐색형 확장 설계

## 요약

현재 통계 화면은 `지출 카테고리 해석 우선형`으로 정리되었지만, 사용자가 직접 시야를 전환하는 탐색 축은 아직 부족하다.  
이번 확장에서는 통계 상단에 `전체 / 수입 / 지출` 3분할 필터를 추가하고, 이 필터가 화면 전체를 함께 바꾸도록 설계한다.

핵심 원칙:

- 필터는 상단 카드만 바꾸는 보조 제어가 아니라 `통계 화면 전체의 렌즈`
- 사용자는 같은 기간 안에서도 `전체`, `수입`, `지출`을 오가며 다른 결을 읽을 수 있어야 함
- 홈과 달력에서 만든 `탐색형 UI` 철학을 통계까지 이어감

## 목표

- 통계에서 `전체 / 수입 / 지출`을 직관적으로 전환할 수 있게 한다
- 필터 변경 시 상단 해석, 숫자 요약, 목록, 차트가 모두 일관되게 바뀌게 한다
- 지출에서는 지금의 `카테고리 해석 우선형`을 유지한다
- 수입에서는 수입 기준의 요약과 분포를 읽을 수 있게 한다
- 전체에서는 수입/지출 균형과 주요 흐름을 함께 읽게 한다

## 비목표

- 기간 비교형 분석
- 예측형 통계
- 사용자 정의 복합 필터
- 다중 선택 필터
- 카테고리 편집 기능
- 서버/AI 기반 통계 요약

## 문제 정의

현재 통계 화면의 한계는 다음과 같다.

- 사용자가 `지출만 보고 싶다`, `수입만 따로 보고 싶다`는 의도를 직접 반영할 수 없다
- 해석은 좋아졌지만, 탐색 관점은 여전히 고정되어 있다
- 같은 기간의 `수입 흐름`과 `지출 흐름`을 분리해서 보기 어렵다
- 결국 통계가 “읽어주는 화면”이기는 해도, “직접 비교하는 화면”으로는 덜 완성되어 있다

## 결정

이번 확장은 `전체 / 수입 / 지출` 3분할 필터를 적용한다.  
그리고 필터 변경 시 `화면 전체`가 함께 바뀌도록 한다.

즉:

- 상단 해석 카드만 바뀌는 것이 아님
- 숫자 패널, 목록, 차트까지 모두 같은 필터 상태를 공유함

## 접근안 비교

### 1. 추천안: 전체 화면 동기형

- 상단 필터 하나가 화면 전체를 제어
- 해석, 숫자, 목록, 차트가 모두 같은 상태를 반영

장점:

- 가장 일관적이다
- 사용자가 무엇을 보고 있는지 혼동하지 않는다
- 달력에서 만든 `필터가 전체 문맥을 바꾼다`는 철학과 맞다

단점:

- 구현 범위가 조금 더 넓다

### 2. 부분 동기형

- 상단 해석과 목록만 필터 적용
- 숫자와 차트는 전체 기준 유지

장점:

- 구현이 단순하다

단점:

- 사용자가 `지금 화면이 무엇 기준인지` 헷갈리기 쉽다
- 탐색형 화면으로서 완성도가 낮다

## 화면 구조

### 1. 기간 선택 패널 유지

기존 `이번 달 / 최근 3개월 / 전체` 및 월 이동은 유지한다.

기간은 세로 축, 필터는 가로 축 역할을 한다.

즉 사용자는:

- 먼저 `언제`를 고르고
- 그다음 `무엇을 볼지`를 고른다

### 2. 통계 타입 필터 추가

기간 패널 아래에 `전체 / 수입 / 지출` 3분할 필터를 추가한다.

형태:

- `SegmentedButton<StatisticsTypeFilter>`

필터 값:

- `all`
- `income`
- `expense`

기본값:

- `all`

### 3. 상단 해석 카드

필터에 따라 역할이 달라진다.

#### `전체`

- 메인: 이번 기간의 수입/지출 균형 또는 흐름 요약
- 근거: 총수입, 총지출, 잔액 또는 거래 수 중 1~2개 사실

예시:

- `이번 기간은 수입이 지출보다 여유 있게 앞서고 있어요.`
- `총수입 300,000원, 총지출 100,000원이 기록됐어요.`

#### `수입`

- 메인: 수입의 중심 흐름을 읽음
- 근거: 수입 총액, 건수, 상위 수입 분류가 있다면 함께 제시

예시:

- `이번 기간 수입은 한두 번 크게 들어오는 흐름에 가까워요.`
- `총수입 300,000원 중 가장 큰 항목이 중심이에요.`

첫 버전에서는 수입 카테고리가 약할 수 있으므로 문구는 무리하게 세분화하지 않는다.

#### `지출`

- 지금 구현한 `지출 카테고리 해석 우선형` 유지

예시:

- `이번 기간엔 식비 쪽 지출이 가장 크게 모였어요.`
- `지출의 42%가 식비에 모였고, 총 5건이 기록됐어요.`

### 4. 숫자 패널

필터에 따라 노출 값이 바뀐다.

#### `전체`

- 총수입
- 총지출
- 잔액
- 거래 수

#### `수입`

- 총수입
- 수입 건수
- 평균 수입액
- 필요 시 최대 수입액

#### `지출`

- 총지출
- 지출 건수
- 평균 지출액
- 절약률 대신 지출 집중도 또는 상위 카테고리 비중 보조 가능

원칙:

- 같은 타일 틀을 재사용하되, 내용만 필터에 맞게 바꾼다

### 5. 목록 영역

필터에 따라 목록의 의미를 바꾼다.

#### `전체`

- 상위 흐름 목록
- 우선은 `지출 카테고리 목록`을 유지하되, 제목을 전체 맥락에 맞춰 조정

#### `수입`

- 수입 항목 또는 수입 출처 성격을 보여주는 목록
- 현재 데이터 구조상 수입 카테고리가 약하면
  - `메모 / 거래처 / 수입 항목` 기반의 단순 순위형 목록으로 제한 가능

#### `지출`

- 상위 지출 카테고리 목록 유지

첫 버전의 안전한 방향:

- `전체`: 상위 지출 카테고리 유지
- `수입`: 수입 거래 요약 목록
- `지출`: 상위 지출 카테고리

### 6. 차트 영역

차트도 필터 상태를 공유한다.

#### `전체`

- 수입 vs 지출 막대 차트
- 지출 카테고리 원형 차트

#### `수입`

- 수입 총액 중심 막대/분포
- 수입 전용 보조 차트가 약하면 우선 막대만 유지 가능

#### `지출`

- 지출 총액 중심 막대
- 지출 카테고리 원형 차트

원칙:

- 차트는 여전히 보조
- 필터 상태와 안 맞는 차트는 보여주지 않는다

## 데이터 설계

### 새 상태

- `StatisticsTypeFilter`
  - `all`
  - `income`
  - `expense`

- `statisticsTypeFilterProvider`

### `StatisticsSnapshot` 확장

현재 snapshot은 필터 없는 통계 기준이다.  
이번 확장에서는 필터 상태에 따라 presentation이 안전하게 분기할 수 있도록 최소 데이터를 더 넣는다.

추가 후보:

- `incomeTransactionCount`
- `expenseTransactionCount` 유지
- `averageIncomeAmount`
- `averageExpenseAmount`
- `largestIncomeAmount`
- `largestExpenseAmount`

### 해석 로직 분리

상단 해석은 필터별로 별도 빌더를 둔다.

예시:

- `buildStatisticsCategoryInterpretation(snapshot)` for expense
- `buildStatisticsIncomeInterpretation(snapshot)` for income
- `buildStatisticsOverviewInterpretation(snapshot)` for all

또는

- `buildStatisticsInterpretation(snapshot, filter)` 하나로 합칠 수 있음

권장:

- 첫 버전은 `buildStatisticsInterpretation(snapshot, filter)` 하나로 시작
- 내부에서 filter 분기

## 필터별 문구 원칙

- 전체: 균형, 흐름, 관계를 읽음
- 수입: 들어오는 방식과 규모를 읽음
- 지출: 어디로 새는지, 어디에 모이는지 읽음

금지:

- 사용자를 평가하는 말
- 과도한 훈계
- 데이터 근거 없는 감정 해석

## 테스트 계획

### 단위 테스트

- `all` 필터일 때 전체 해석 반환
- `income` 필터일 때 수입 해석 반환
- `expense` 필터일 때 지출 해석 반환
- 수입/지출 건수 0일 때 비어 있는 상태 문구 반환

### 위젯 테스트

- 통계 화면에 `전체 / 수입 / 지출` 필터가 보이는지
- 필터를 바꾸면 상단 해석 카드 문구가 달라지는지
- 필터를 바꾸면 숫자 패널 값이 달라지는지
- 필터를 바꾸면 목록 제목 또는 내용이 달라지는지

### 회귀 테스트

- 기간 변경 동작 유지
- 달력/내역 바로가기 유지
- 기존 차트 렌더링이 필터 상태에 따라 안전하게 유지되는지

## 구현 범위

이번 구현 포함:

- 통계 타입 필터 provider
- 필터 UI
- 필터에 맞는 상단 해석 전환
- 필터에 맞는 숫자 패널 전환
- 필터에 맞는 목록/차트 전환
- 테스트 추가

이번 구현 제외:

- 고급 비교 분석
- 수입 카테고리 정교화
- 멀티 필터
- 검색형 통계

## 결정 요약

- 통계는 `전체 / 수입 / 지출` 3분할 필터로 간다
- 필터는 상단만이 아니라 화면 전체를 같이 바꾼다
- `지출`은 현재의 카테고리 해석 우선 구조를 유지한다
- `수입`과 `전체`는 각각 그 상태에 맞는 상단 해석과 숫자 구성을 갖는다
