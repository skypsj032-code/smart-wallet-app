# Recurring Spend Detail Sheet Spec

작성일: 2026-05-23  
기능 slug: `recurring-spend-detail-sheet`  
기능 크기: `medium`  
상태: draft

## 왜 하는가

- 반복지출 카드와 바텀시트는 `무엇이 반복지출인지`까지는 보여준다.
- 그다음에는 사용자가 `왜 이 항목이 반복지출로 잡혔는지`를 이해할 수 있어야 한다.
- 이 설명이 있어야 자동 판정이 단순 추정보다 신뢰 가능한 해석으로 받아들여진다.

## 문제 정의

- 현재 반복지출 흐름은 목록 중심이다.
- 사용자는 항목을 보고도 `왜 반복으로 본 건지`, `어떤 거래들이 묶였는지`, `다음에도 이어질 가능성이 왜 높은지`를 충분히 확인할 수 없다.
- 따라서 항목 단위 상세 계층이 필요하다.

## 핵심 원칙

- 1순위는 `왜 반복지출로 잡혔는지 설명`이다.
- 2순위는 `최근 거래 내역 확인`이다.
- 설명은 모델의 실제 데이터와 규칙에 근거해야 한다.
- 설명 톤은 확정적 단정보다 `이렇게 판단했어요`에 가깝게 간다.

## 사용자 변화

기존:

- 반복지출 목록에서 이름, 금액, 유형만 본다.
- 항목 판정 이유는 추측해야 한다.

변경 후:

- 항목을 눌러 반복 판정 이유를 바로 본다.
- 어떤 거래들이 묶였는지 최근 흐름으로 확인한다.
- 최근 결제일, 다음 예상 시점, 지난달 대비를 함께 이해한다.

## 범위

이번 기능에 포함:

- 반복지출 바텀시트 항목 탭 동작
- 항목 상세 시트
- 반복 판정 이유 섹션
- 최근 거래 내역 리스트
- 최근 결제일 / 다음 예상 시점 / 지난달 대비 요약

이번 기능에서 제외:

- 반복지출 항목 수정
- 반복 판정 제외/숨김
- 카테고리 변경
- AI 자연어 요약 확장
- 판정 규칙 직접 편집

## 정보 구조

상세 시트는 아래 순서로 구성한다.

### 1. 헤더

- 항목명
- 반복 유형
- 이번 달 금액

목적:

- 사용자가 지금 어떤 반복지출을 보고 있는지 즉시 이해한다.

### 2. 반복으로 본 이유

이 섹션이 상세 시트의 핵심이다.

보여줄 내용 예시:

- 최근 2개월 이상 비슷한 이름으로 반복됐어요
- 금액 차이가 크지 않아요
- 월간 간격이 비슷해서 고정비처럼 보였어요
- 최근 45일 동안 3번 이상 보여서 생활 반복지출로 봤어요

표현 방식:

- 규칙형 bullet 2~4개
- detector 결과와 일치하는 이유만 노출

### 3. 최근 거래 내역

보여줄 내용:

- 최근 거래일 순 리스트
- 날짜
- 금액
- 상호 또는 메모

목적:

- 사용자가 실제 묶인 거래들을 눈으로 확인한다.

### 4. 요약 정보

- 최근 결제일
- 다음 예상 시점
- 지난달 금액
- 이번 달 금액
- 지난달 대비 증감

목적:

- 시간성과 영향도를 같이 이해한다.

## 판정 이유 매핑 원칙

상세 시트의 설명은 detector 규칙에 직접 매핑한다.

예:

- `RecurringSpendKind.fixed`
  - 월간 간격 유사
  - 금액 편차 작음
- `RecurringSpendKind.subscription`
  - 구독 키워드 존재
  - 반복 횟수 충족
  - 금액 편차 작음
- `RecurringSpendKind.lifestyle`
  - 최근 45일 내 3회 이상
  - 같은 이름/카테고리 흐름
  - 점수 기준 충족

즉 설명 문구는 새 추론을 만들지 않고, 이미 판정에 사용한 규칙을 번역해서 보여준다.

## UI 원칙

- 항목 상세는 바텀시트 위에 다시 바텀시트로 여는 방식이 우선
- 한 화면 안에서 끝내서 흐름을 짧게 유지
- 설명 섹션이 거래 리스트보다 먼저 온다
- 거래 리스트는 길어져도 스크롤 가능해야 한다

## 문구 톤

피해야 할 톤:

- 반복지출이 맞습니다
- 불필요한 지출입니다
- 줄여야 합니다

권장 톤:

- 이렇게 반복 흐름으로 판단했어요
- 최근 거래 패턴이 비슷하게 이어졌어요
- 금액과 간격이 비슷해서 반복지출로 봤어요

## 데이터 요구사항

이미 있는 데이터:

- `RecurringSpendGroup`
- `kind`
- `score`
- `currentMonthAmount`
- `previousMonthAmount`
- `transactions`

상세 시트에 추가 계산이 필요한 값:

- 판정 이유 문자열 리스트
- 최근 결제일
- 다음 예상 시점
- 증감 문구

이 값들은 presentation helper 또는 detector 결과 확장으로 계산할 수 있다.

## 성공 기준

- 사용자가 항목 탭 후 `왜 반복으로 봤는지`를 바로 이해할 수 있다.
- 거래 리스트는 설명을 뒷받침하는 역할로 읽힌다.
- 자동 판정이 임의 추정처럼 느껴지지 않는다.
