# Recurring Spend Not Recurring Action Spec

작성일: 2026-05-25  
기능 slug: `recurring-spend-not-recurring-action`  
기능 크기: `medium`  
상태: draft

## 왜 하는가

- 반복지출 상세 시트는 현재 `왜 반복지출로 잡혔는지`를 설명할 수는 있지만, 사용자가 그 판단을 부정할 방법은 없다.
- 자동 해석 기능은 설명만으로는 충분하지 않고, 사용자가 `이건 반복 아님`이라고 보정할 수 있어야 신뢰가 유지된다.
- 많이 쓰이는 앱들은 이 보정 액션을 리스트 인라인이 아니라 상세 화면 또는 옵션 메뉴 안에서 제공한다.
  - Copilot은 거래 또는 recurring 상세에서 `Not Recurring`이나 편집을 제공한다.
  - Monarch는 recurring 항목의 메뉴나 거래 상세에서 `Mark merchant as not recurring`을 제공한다.
  - Rocket Money는 recurring 상세의 옵션에서 제거한다.

## 문제 정의

- 같은 `groupKey`가 잘못 반복지출로 잡혀도 사용자는 현재 숨기거나 제외할 수 없다.
- 잘못 감지된 항목이 홈 카드, 목록 바텀시트, 상세 시트에 계속 노출되면 detector 전체 신뢰가 떨어진다.
- 이 보정은 단순 화면 숨김이 아니라 이후 반복지출 해석에서 제외되는 형태여야 한다.

## 목표

- 사용자가 반복지출 상세 시트에서 `반복 아님` 액션을 실행할 수 있게 한다.
- 해당 `groupKey`는 이후 반복지출 detection 결과에서 제외한다.
- 제외 후에는 홈 카드, 목록 바텀시트, 상세 시트 진입 흐름에서 모두 사라진다.
- 보정 상태는 앱 재시작 후에도 유지된다.

## 비목표

- 반복지출을 다시 복구하는 관리 화면
- `숨기기`와 `반복 아님`을 분리한 2중 액션
- detector 규칙 자체를 사용자별로 학습시키는 기능
- 거래 단위의 세밀한 포함/제외 편집

## 제품 문법

- 액션 위치는 `반복지출 상세 시트 하단`이다.
- 목록 바텀시트에는 인라인 액션을 두지 않는다.
- 이유 섹션 아래 인라인 버튼도 두지 않는다.
- 사용자가 액션을 누르면 확인 다이얼로그를 한 번 거친다.
- 문구 톤은 훈계형이 아니라 확인형으로 유지한다.

예상 흐름:

1. 홈 카드에서 반복지출 상세 시트 진입
2. 상세 시트 하단의 `반복 아님` 버튼 탭
3. 확인 다이얼로그에서 승인
4. 해당 항목은 반복지출 해석에서 제외
5. 상세 시트 닫힘, 목록과 홈 카드가 갱신됨

## 저장 모델

이번 버전은 `groupKey` 기준 영속 제외 모델로 간다.

새 테이블:

- `recurring_spend_overrides`

필드:

- `group_key`
- `action_type`
- `created_at`
- `last_modified_at`

초기 action type:

- `not_recurring`

설계 이유:

- 현재 detector는 `groupKey`를 중심으로 클러스터링한다.
- 거래 단위 보정보다 구현이 단순하고 현재 구조와 맞는다.
- 일시적 UI 숨김이 아니라 앱 전체 해석 제외를 만들 수 있다.

## 데이터 플로우

1. detector가 기존처럼 `RecurringSpendGroup` 후보를 만든다.
2. override 저장소에서 `not_recurring` 처리된 `groupKey` 목록을 읽는다.
3. detector 결과에서 해당 `groupKey`를 제외한다.
4. 대시보드 summary는 제외된 결과만 UI로 전달한다.
5. 사용자가 `반복 아님`을 누르면 override가 저장되고 summary stream이 갱신된다.

## UI 상세

### 1. 상세 시트 하단 액션

- 버튼 라벨: `반복 아님`
- 배치: 상세 시트 하단, 요약 정보 아래
- 스타일: 위험 색보다는 보조/경고 성격이 약한 outlined 또는 tonal 계열

### 2. 확인 다이얼로그

제목 예시:

- `이 항목을 반복지출에서 제외할까요?`

본문 예시:

- `이후에는 이 항목이 반복지출 카드와 목록에 보이지 않아요. 거래 자체가 삭제되지는 않아요.`

버튼:

- `취소`
- `반복 아님으로 제외`

### 3. 실행 후 동작

- 상세 시트를 닫는다.
- 목록 바텀시트가 열려 있으면 그 상태에서 리스트를 갱신한다.
- 홈 카드에 그룹이 더 없으면 카드 자체가 숨을 수 있다.

## 기술 설계 원칙

- detector 내부 규칙은 유지하고, 후처리 필터로 override를 적용한다.
- override는 detector와 UI 사이가 아니라 summary 계층에서 읽히게 한다.
- UI는 `반복 아님` 액션만 호출하고, 해석 제외는 application/data 계층이 책임진다.
- stream 기반 대시보드 갱신 패턴을 깨지 않는다.

## 범위

이번 기능에 포함:

- override용 Drift 테이블 추가
- schema version 증가와 마이그레이션
- override 조회/저장용 application 또는 data helper
- dashboard summary에 override 반영
- 상세 시트 하단 `반복 아님` 액션
- 확인 다이얼로그
- detector/dashboard/widget 테스트 보강

이번 기능에서 제외:

- override 목록 관리 화면
- 복구 액션
- `숨기기` 액션
- detector 규칙 수정 UI

## 성공 기준

- 사용자가 잘못 감지된 반복지출을 상세 시트에서 제외할 수 있다.
- 제외한 항목은 홈/목록/상세 전반에서 다시 나타나지 않는다.
- 앱을 재시작해도 제외 상태가 유지된다.
- 거래 원본 데이터는 삭제되지 않는다.

## 실패 신호

- 상세 시트에서 제외했는데 홈 카드에는 계속 남아 있는 경우
- 같은 항목이 다음 앱 실행에서 다시 반복지출로 나타나는 경우
- 사용자가 `반복 아님`과 `삭제`를 혼동하는 경우
